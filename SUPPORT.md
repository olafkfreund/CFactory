# Getting Support

A quick map of where to go for what.

| You want to...                            | Go to                                                          |
|--------------------------------------------|-----------------------------------------------------------------|
| Ask a question or share an idea            | [Open an issue](https://github.com/olafkfreund/CFactory/issues/new) — this repo does not have GitHub Discussions enabled |
| Report a bug                               | [Open an issue](https://github.com/olafkfreund/CFactory/issues/new) — there is no bug-report template yet, so describe repro steps directly |
| Read the docs                              | [`README.md`](README.md), [`guides/`](guides/), [`techdocs/`](techdocs/), [`CLAUDE.md`](CLAUDE.md) |
| Set up the project                         | [CONTRIBUTING.md → Development setup](CONTRIBUTING.md#development-setup) |
| Understand how a change ships              | [RELEASE.md](RELEASE.md)                                        |
| Contribute code                            | [CONTRIBUTING.md](CONTRIBUTING.md)                               |
| Report a security issue                    | [SECURITY.md](SECURITY.md) — **do not open a public issue**    |

## Before opening an issue

1. **Search existing issues first.** Most problems are already known.
2. **Reproduce on the latest `dev`** when possible — `dev` is the default
   and integration branch; `main` only receives promotion merges from it.
3. Include: what you were doing, what you expected, what happened instead,
   and the commit SHA (`git rev-parse HEAD`) you were on.

## Response times

CFactory has one maintainer and no commercial SLA. Issues are triaged as
time allows.
