# Intent: CFactory copilot defaults to the current Claude model

## Problem

The copilot model default, its Settings placeholder, the Helm value, `.env.example` and the docs all name `claude-opus-4-8`. The owner wants the new models enabled across the portals.

## Proposed outcome

A fresh install uses `claude-opus-5-5`. Settings offers the new Claude ids as suggestions. `claude-opus-4-8` and any other saved id keep working.

## Affected users and systems

CFactory backend `config.py`, Settings view, Helm chart, `.env.example`, techdocs. A deployed pod that stored a model in its settings keeps that value.

## Constraints

- Prove `claude-opus-5-5` works from the running pod first (done 2026-11-19: Agent SDK query returned OK, model claude-opus-5-5).
- Model id stays a free string; no allow-list.
- Only the Claude provider is in scope: CFactory has no Codex or Gemini model table.
