# Plan: /api/events requires a write-scoped key

Approved decisions (from the spec):

- CFactory checks `/api/events*` for a WRITE-scoped key in the existing
  `enforce_api_key` middleware, under `CFACTORY_EVENTS_AUTH_MODE`
  (`events_auth_mode`, default `warn`). `warn` logs (path, would-be status,
  running count; never the key), counts, and accepts. Any other value,
  including `enforce`, returns the 401/403. Unknown fails closed.
- `api_dev_open` / `mcp_dev_open` parse strictly: only case-insensitive `true`.
- Senders send `Authorization: Bearer $APP_API_TOKEN` via an `_auth_headers(url)`
  copied from PFactory#930: token only when `url`'s (scheme, netloc) equals the
  configured `<X>FACTORY_COMPLETION_WEBHOOK`'s. Never log the token.
- Ship warn only. The enforce flip is a later gitops change.

One PR per repo into `dev`, each `Refs olafkfreund/CFactory#501`; the CFactory
PR also `Closes #501`.

## Steps

1. CFactory `apps/backend/cfactory/config.py` (`api_dev_open`, `mcp_dev_open`,
   new `events_auth_mode: str = "warn"`; one `field_validator(mode="before")`
   for both flags) and `apps/backend/cfactory/app.py` (`_EXEMPT_PREFIXES`,
   `enforce_api_key`): the WRITE check with warn/enforce. Update
   `tests/test_token_gated_api.py::test_event_webhook_is_exempt` and add tests
   (warn counts and logs without the key; enforce 401/403/200; unknown → 401;
   strict flag table). Docs: `docs/dev/environment-reference.md`,
   `.env.example`.
   → `cd apps/backend && .venv/bin/python -m pytest ../../tests/test_token_gated_api.py ../../tests/test_mcp.py -q`, ruff.
   Traps: `tests/conftest.py` sets `CFACTORY_API_DEV_OPEN=true`; the middleware
   reads the global keystore, so tests use `set_keys` + `reset_keystore`, and
   `reset_settings()` after env changes.
2. AIFactory `apps/web-server/server/services/completion.py`: add
   `_auth_headers(url)` next to `_webhook_url()`; use it in `_notify_worker`,
   `_notify_worker_progress`, `notify_completion`. `services/outbox.py`
   `_default_sender(url, …)`: import it from `.completion` lazily and add it
   (the row's URL is why the origin check matters). Test in
   `apps/web-server/tests/test_completion_emitter.py` / `test_completion_outbox.py`.
   → targeted pytest + ruff.
   Traps: `completion.py` imports `outbox` lazily; keep the import in
   `_default_sender` lazy too to avoid a cycle.
3. PFactory `apps/backend/plan/completion.py`: add `_auth_headers(url)`; use in
   `_post_webhook`. `apps/backend/agents/triager.py::_notify_completion`: import
   and use it. Tests in `tests/test_plan_completion.py`,
   `tests/test_triager_completion_webhook.py`.
   → targeted pytest + ruff.
4. TFactory `apps/backend/agents/completion_outbox.py`: add `_auth_headers(url)`;
   use in `_default_deliver`. `apps/backend/agents/triager.py` direct POST:
   import and use it. Tests in `tests/test_completion_outbox.py`,
   `tests/test_triager_completion_webhook.py`.
   → targeted pytest + ruff.
